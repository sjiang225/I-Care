# 升级第 1 步：停用自动情绪记录与旧图表

日期：2026-09-28。依据：9 月 11 日会议合并纪要 R04，以及本轮确认的分步升级计划。

## 修改范围

- 移除聊天页的情绪图表入口、旧图表组件和“已记录情绪”提示。
- 移除前端旧查询方法、图表样式及 Recharts 依赖；登录文案改为保存和继续对话。
- Emotion 和 Peer 继续提供对话支持，但不调用模型评估或保存压力等级、情绪标签。
- Coordinator 不读取旧压力摘要；各回答角色不接收旧压力提示，也不因旧分数额外推荐资源。
- 资料检索、主题视频、用户请求的本地资源、虚拟同伴标识、危机提示及账户对话保存继续工作。

## 旧数据与接口

- 保留 `wellbeing_logs` 表及已有数据；本次没有删除、清空或迁移真实数据库。
- 移除旧评分工具、日志助手、趋势判断模块，以及应用数据库中的旧记录读写方法。
- `GET /api/wellbeing` 对所有请求统一返回 `410 Gone` 和 `Cache-Control: no-store`，不查询数据库。
  这也关闭了通过游客 `session_id` 读取账号旧情绪记录的入口。
- 后续主动自评应使用独立的数据模型，不能把这些推断记录当作用户提交的量表结果。
- 原聊天历史仍保留；本次不改写历史消息正文。

## 验证

回归测试：`backend/tests/test_wellbeing_retirement.py`。从 `backend/` 执行：

```bash
./.venv/bin/python -m unittest discover -s tests -v
```

测试采用临时 SQLite、合成记录和本地确定性模型，验证：

1. 游客与登录用户的知识、资源、情绪、同伴、混合需求和危机对话都能完成；不读写旧情绪表，不发送评分信号。
2. 同一个问题在“已有高压力旧记录”和“无旧记录”两种条件下，模型输入和推荐结果一致。
3. 匿名、有效令牌和无效令牌访问旧接口均不能获取记录，包括伪造账号对应的 `session_id`。
4. 重新初始化数据库不会删除或改变旧记录。
5. 旧 `log_wellbeing` 工具不可再调用或写入。

2026-09-28 验证结果：5 项后端测试通过（包含游客/登录用户、多种对话路径和接口访问场景）；
TypeScript 检查及 Next.js 生产构建通过。Chrome 中使用临时 Mock 后端检查了首页、聊天发送和登录弹窗，
确认旧入口、记录提示及登录页情绪追踪介绍已移除。本轮未调用真实模型，也未进行真实手机语音测试。

发布时需更新并重启后端、更新前端，让已打开的浏览器刷新页面。旧版前端访问旧接口会得到停用响应。
